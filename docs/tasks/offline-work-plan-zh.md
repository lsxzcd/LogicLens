# 不需要远控时的工作安排

> 场景：**暂时无法远控实验室机器**，所以所有依赖那台机器的工作都要挂起。
> 但**大部分关键工作并不依赖它** —— 这份清单列出这些。

---

## 一、为什么"没远控"不等于"没事做"

我们的工作分三类：

| 类别 | 依赖实验室机器吗 | 现在能做吗 |
|---|---|---|
| **智能体逻辑、技能包、测试** | ❌ 不依赖 | ✅ **能** |
| **本地模型评测（小规模）** | ❌ 不依赖（开发机有 1.5B） | ✅ **能** |
| **失败样本分析与技能提炼** | ❌ 不依赖（数据在本地） | ✅ **能** |
| 综合崩溃排查、容器验证 | ✅ 依赖 | ⏸️ 挂起 |

**换句话说：只有"那台机器特有的问题"要等，其他都能推进。**

它会输出：

### 任务 M-offline-3：实现"结构检查的自动修复"（可选，价值高）

**背景**：`Prob002` 三次尝试后仍失败，模型生成了：

```verilog
output wire out
wire out;                      ← 重复声明
always @(posedge clk) begin    ← clk 未声明
    out <= 0;                  ← 对 wire 过程赋值
end
```

**结构检查已经检出问题，但模型改不掉**（这是那张"未解决限制"技能卡记录的模式）。

**可以做的事**：**让 lint 不只会"报告"，还能"自动修复"最明确的那一类**：

| 现状 | 改进 |
|---|---|
| lint 报告 `combinational_uses_edge` | **机械地把它改成组合逻辑**（去掉 posedge、`<=` 改 `=`） |

**为什么可行**：当接口里**根本没有时钟端口**时，"去掉时钟边沿改成组合逻辑"是
**唯一正确解**，不是猜测。这是机械变换，不是猜测。

**风险评估**：需要小心——不是所有情况都能机械修。**必须加测试**：
- 组合逻辑题（无时钟端口）→ 可以修
- 时序题（有时钟端口）→ **不能动**
- 修复后必须仍能通过官方 testbench

> ⚠️ 这一项**改动判定相关逻辑**，建议由队长做，或至少评审后再合。
