## 每份任务书包含什么

统一结构，便于队友直接上手：

1. **背景 30 秒版**——项目在做什么、你的方向是什么
2. **关键认知**——为什么这件事重要（不是泛泛而谈）
3. **环境准备**——带预期输出的命令，10 分钟完成
4. **具体任务**——带完整命令、预期输出、参考代码
5. **交付物与验收标准**——什么算做完了
6. **边界：不要动哪些文件**——避免互相踩踏
7. **提交方式**——含**干净克隆自检**（关键步骤）
8. **卡住了怎么办**——常见现象与处理
9. **参考文档**——按需查阅

## 给协调人（你）的提醒

### 三条不能破的纪律

1. **干净克隆自检**——推代码前必须做。曾经有测试依赖本机存在但仓库未提交的文件，
   **本机通过、CI 三个检查全挂**。
2. **`vivado/run_flow.tcl` 和 `agent/controller.py` 同时只允许一人改**——
   这两个文件决定判定口径，并行改会让评测流程无声分叉。
3. **不能用 `--mock` 数据写报告结论**——赛题要求真实可复现。

### 每个 PR 都要问的问题

- [ ] 结论有**证据**吗？（命令输出、日志、对照实验数据）
- [ ] 有没有把"**未做/做不了**"也说清楚？（报告的可信度来自诚实的边界声明）
- [ ] 测试是否**离线可跑**？（CI 不能依赖外部服务）
- [ ] 有没有**依赖未提交的文件**？（干净克隆自检）

### 技能包的特殊要求

赛题要求技能卡记录"**验证题数、有效性结论**"。因此：

- ❌ **不接受**没有实测效果的技能卡
- ❌ **不接受**全是"有效"结论的技能包——那不可信
- ✅ **必须有**至少一张记录"无效"或"部分有效"

现有 6 张卡里已经有一张 `capability-limit-clock-removal` 是"未解决"状态的，
这是刻意的设计，请保持这个习惯。
