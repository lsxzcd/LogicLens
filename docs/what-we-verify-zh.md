# 我们到底要验证什么

> 这份文档回答一个问题：**每一层验证，验证的是"什么"，拿到的结论"能证明什么"。**
> 当你（或队友）不确定"做这一步有什么意义"时，回来看这份文档。

---

## 一、先明确交付物

赛题要求的提交物（选题指南 3.1.5.1）：

```
<team_name>-agent/
├── Dockerfile          基于官方基础镜像构建
├── model/MODEL.md      模型来源、版本、量化方式、显存占用、上下文配置
├── agent/              智能体源码
├── skill/              技能包
├── serve/              推理服务配置与启动脚本
├── run.sh              单题入口：读题 → 产出代码
├── run_baseline.sh     基线入口：同一推理服务，绕过智能体与技能包
└── REPORT.md           设计报告
```

**核心机制**：容器在**断网沙箱**中运行，**自行完成从读题到产出代码**。
所以模型权重必须能随提交物走，不能依赖评测时联网下载。

## 二、赛题怎么评分（这决定了我们要验证什么）

> 权重来自选题指南 3.1.4 / 3.1.5：**能力 30 / 增益 40 / 墙钟 10 / 工程质量 20**

### 2.1 三级递进判定（**能力分的基础**）

```
题目 → ┌─────────┐  不过就停
       │ 可编译  │  xvlog + xelab
       └────┬────┘
            ↓ 通过了才继续
       ┌─────────┐  不过就停
       │ 仿真通过│  xsim，与参考实现逐拍对比
       └────┬────┘
            ↓ 通过了才继续
       ┌─────────┐
       │ 可综合  │  synth_design，目标器件 xczu3eg-sbva484-1-e，5ns 时钟
       └─────────┘
```

**关键**：**逐级递进**。只有前一级过了才进下一级。
（这是为什么我们统计通过率时必须用 `synthesis_attempted` 区分"没跑"和"跑了没过"。）

### 2.2 性能指标

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| `pass@1` | 一次尝试就成功的比例 | 主指标 |
| `pass@5` | 五次尝试内至少成功一次的比例 | 稳定性 |
| **增益** | 我们 vs **同模型裸跑基线** | **权重最高（40 分）** |
| 墙钟 | 单题耗时 | 10 分 |
| 工程质量 | 代码结构、技能包、文档 | 20 分 |

### 2.3 增益的公平性前提（**容易出错的地方**）

> 增益 = 我们的通过率 − **同一模型、同一推理服务、同一上下文配置**下的裸跑通过率

**基线要求**：
- ✅ 同一推理服务
- ✅ 同一采样配置（temperature / top_p / max_tokens / seed）
- ✅ **绕过智能体与技能包**（提示词只含题目原文）
- ✅ 单次生成，不重试

**任何一项不一致，增益数据就不可信。** 我们已经修过两个相关缺陷（见 `docs/status-log-zh.md` 缺陷 20、21）。

## 三、★ 核心：每一层验证"证明什么"

这张表是本文档的核心。**做验证时先看这一列：拿到的结论能证明什么、不能证明什么。**

| # | 验证项 | 验证的是**什么** | 拿到的结论能证明 | **不能**证明 |
|---|---|---|---|---|
| L0 | `python -m unittest discover -s tests` | 纯逻辑正确性：解析、判定字段、评分、提示词构造 | 代码**没有逻辑回归**；**零第三方依赖可运行** | 任何与真实工具交互的正确性 |
| L1 | `tools/check_parsing.py` | 规格契约解析的**准确率** | 在 156 道真实题目上解析正确率 153/156 | 解析结果能否变成正确 RTL |
| L2 | `experiments/p05_verify.py` | **三级判定流程本身**能跑通 | 编译/仿真/综合三级的**工具调用链路正确**；综合真的执行；5ns 约束真的生效；仿真失败后不再跑综合 | 模型写代码的能力 |
| L3 | `experiments/verilogeval_verify.py` | 官方 testbench 是**真判据** | testbench 能**拒错纳对**（参考实现通过 + 故障注入被拒） | 我们的智能体写得对不对 |
| L4 | `agent/model_client.py` + 桩服务 | **模型调用链路**正确 | 请求格式、采样配置、响应解析、重试策略都对 | 真实模型的质量 |
| L5 | `experiments/fairness_verify.py` | **基线与智能体配置一致** | 增益比较在**配置层面**是公平的 | 增益数值本身 |
| L6 | `experiments/model_e2e_verify.py` | 题目→模型→代码→判定的**完整闭环** | 整条链路能端到端工作 | 通过率高低 |
| L7 | `eval.py` 实测 | **通过率与增益** | pass@1/pass@5、增益幅度、墙钟 | 在别的模型/硬件上的表现 |
| L8 | `Dockerfile` 构建 + `--network none` | **断网容器自包含** | 提交物在断网沙箱中能跑 | 在赛题方环境中的表现（可能有差异） |

**看这张表能明白一件事**：

> **L0~L6 证明"我们的机器是对的"；L7 才是"我们的方法有多好"。**

**不要混淆这两类。** 一台机器的正确性，和方法的性能，是两件事。

## 五、**关键区分**：三个不同的"环境"

这是最容易混淆的地方，必须分清：

| 环境 | 是什么 | 我们的权限 | 用途 |
|---|---|---|---|
| **① 开发机**（你自己的电脑） | Intel 核显，Windows | 完全控制 | 写代码、跑单测、小规模验证 |
| **② 实验室机器**（老师的，`jcsylvm1`） | **AMD R9700**，Windows，**Vivado 已装** | ⚠️ **可能不允许安装软件** | **移植验证**：代码能否在别人的机器上跑 |
| **③ 赛题评测沙箱**（未来） | 官方基础镜像容器，断网 | 无 | **最终评分** |

### 为什么这个区分重要

| 问题 | 答案取决于哪个环境 |
|---|---|
| 代码有没有逻辑 bug？ | ① 开发机 |
| 代码能不能在**别的机器**上跑？ | **② 实验室机器** |
| 三级判定在目标器件上真的能跑吗？ | ② 实验室机器（有 Vivado） |
| 我们的方法通过率多高？ | 需要模型服务，哪个环境都行 |
| 提交物在断网容器里能跑吗？ | **③ 赛题沙箱**（但我们可以本地模拟） |

**「移植到实验室机器」这件事本身就是一个独立且有价值的验证项**——
它检验的是"我们的代码是否真的零依赖"，这正是赛题"容器自包含"要求的提前演练。

## 六、所以，我们的验证路线

### 阶段 1：零安装验证（**现在就能做，零风险**）

在**实验室机器**上，不装任何东西：

```powershell
# 移植代码
cd E:\
git clone https://github.com/lsxzcd/LogicLens.git
cd LogicLens

# L0：零依赖可运行
python -m unittest discover -s tests          # 期望 124 个全绿

# L1：解析正确
python tools\check_parsing.py                 # 期望 0 unexplained

# L2：三级判定（Vivado 已装）
$env:LOGICLENS_VIVADO = "E:\2025.2\Vivado\bin\vivado.bat"
python experiments\p05_verify.py              # 期望 3 cases, 0 failed, 0 env-blocked
```

**这一阶段证明**：
> ✅ 我们的代码**零第三方依赖**，在别人的机器上即可运行
> ✅ 三级判定在**目标器件**上真的能跑通

**这两个结论是"工程质量 20 分"和"能力 30 分"的基础，而且不需要任何安装权限。**

### 阶段 2：模型性能验证（**需要模型服务**）

| 方案 | 前提 | 做什么 |
|---|---|---|
| 2a. 在**开发机**上 | 已有 1.5B（CPU） | 扩大题量到 20~30 道，观察规则在难题上是否还成立 |
| 2b. 在**实验室机器**上 | **需要安装权限** | 实测显卡是否可用、显存占用、真实通过率 |
| 2c. 在**有独立显卡的机器**上 | 硬件 | 正式性能数据 |

### 阶段 3：容器验证（**需要 Docker**）

模拟赛题沙箱，验证提交物自包含 + 断网可跑。

## 八、一句话总结

**我们要验证三件不同的事，不要混为一谈：**

| # | 验证什么 | 说明"什么" |
|---|---|---|
| **1** | **正确性** | 我们的机器（代码）本身对不对 —— L0~L6 |
| **2** | **有效性** | 我们的方法有多好（通过率、增益）—— L7 |
| **3** | **可移植性** | 提交物在别人的/断网的环境中能不能跑 —— 零安装验证 + L8 |

**当前最该做的是「3」的零安装部分**：它零风险、立刻可做，
而且是赛题"容器自包含"要求的提前演练。

**「2」需要模型服务 + 显卡确认，等老师答复。**
