# 智能体部署方案

> 回答两个问题：**部署怎么做**、**接下来做什么**。
>
> ⚠️ 核心认知：**"部署"要分成两件事**——我们的代码、和模型服务。
> 两者的部署难度和方式完全不同，混在一起想会乱。

---

## 一、先分清：部署的是什么

```
┌─────────────────────────────────────────────────────────┐
│  我们的交付物                                            │
│                                                         │
│  ① 代码部分（我们写的）        ② 模型部分（下载来的）      │
│     agent/ skill/ tools/         Ollama 运行时            │
│     vivado/ eval.py ...          模型权重（几 GB）        │
│                                                         │
│  ✅ 零第三方依赖                 ⚠️ 需要安装运行时         │
│  ✅ 111 个文件 / 0.22 MB         ⚠️ 需要下载权重           │
│  ✅ 已证明可移植                 ⚠️ 需要 GPU 驱动          │
└─────────────────────────────────────────────────────────┘
```

**关键区别**：

| | ① 代码部分 | ② 模型部分 |
|---|---|---|
| 谁提供 | **我们写** | 开源模型 + 推理运行时 |
| 大小 | 0.22 MB | 5~20 GB |
| 能否离线自带 | ✅ 完全自包含 | ⚠️ 权重要一起打包 |
| 部署难度 | **极低** | 中等 |
| 当前状态 | ✅ **已验证可移植** | ⚠️ 实验室已装、赛题容器未做 |

**好消息**：①已经部署成功了（C 在实验室机器上跑通了 124 个测试）。
**待解决**：②在**赛题容器**里的部署方式。

## 三、场景 C 的关键决策：模型权重怎么进容器

| 方案 | 镜像大小 | 优点 | 缺点 |
|---|---|---|---|
| **A. 权重打进镜像** | +5~20 GB | 完全自包含，不依赖挂载 | 镜像巨大；换模型要重建 |
| **B. 权重放挂载卷** | 几百 MB | 换模型只改环境变量 | **依赖挂载正确**，可能不满足"自包含" |
| C. 构建时下载 | — | 镜像小 | ❌ **断网环境不可行** |

**我们的默认选择是 B**（`Dockerfile` 已按此实现，同时提供了 `Dockerfile.bundled` 做 A）。

**但这个决策需要确认**：赛题说"容器在断网沙箱中运行，自行完成从读题到产出代码"——
如果评测方**挂载权重卷**，B 可行；如果要求**镜像完全自包含**，必须用 A。

**→ 这应该问赛事方 / 查《评分细则》。**

## 四、接下来做什么（按优先级）

### P0：解除 Vivado 综合阻塞

| 步骤 | 谁 | 耗时 |
|---|---|---|
| 跑 `help synth_design` 确认参数名 | C | 1 分钟 |
| 用确认的参数试单进程综合 | C | 2 分钟 |
| 查事件日志 `Faulting module name` | C | 2 分钟 |
| 请老师协调在另一台机器跑最小案例 | 老师 | — |

**如果能解决** → 实验室机器可产出**完整三级数据**，价值最大。
**如果解决不了** → 接受为环境限制，见 §5。

### P1：⭐ 在实验室机器跑 7B 模型的真实评测

**这一项最有价值，而且不受综合崩溃影响**（逐级递进，仿真独立于综合）。

```powershell
cd E:\LogicLens-87cc7d0a72c2617557b9a0abf4d6a50f9c832d0d\LogicLens-87cc7d0a72c2617557b9a0abf4d6a50f9c832d0d
$env:LOGICLENS_MODEL_URL  = "http://127.0.0.1:11434/v1"
$env:LOGICLENS_MODEL_NAME = "qwen2.5-coder:7b"
$env:LOGICLENS_SEED       = "1"
$env:LOGICLENS_VIVADO     = "E:\2025.2\Vivado\bin\vivado.bat"

python eval.py --dataset experiments\data\verilogeval --mode agent --limit 5 --samples 1 `
    --out experiments\results\lab_7b_probe
```

**产出**：7B 模型在 5 道真实题目上的 `compile_pass_rate` 和 **`simulation_pass_rate`**。

> ⚠️ **解读警告**：`success_rate` 会是 0（要求三级全过），
> **不要把这个 0 当作"模型不行"**——只看 `simulation_pass_rate`。

**这一步产出的是项目第一份真实的功能正确性数据。**

### P2：做基线对照（**赛题权重最高的一项**）

赛题"增益 40 分"要求对比**同模型裸跑**。所以我们还要跑：

```powershell
python eval.py --dataset experiments\data\verilogeval --mode baseline --limit 5 --samples 1 `
    --out experiments\results\lab_7b_baseline
```

**`eval.py` 会自动检查两侧模型配置是否一致并报警**（这是我们上一轮修的公平性保障）。

**有了两侧数据，就能算出真实的增益。** 这是报告第 7 节的核心内容。

### P3：解决容器部署

| 步骤 | 阻塞 |
|---|---|
| 问赛事方：官方基础镜像是哪个 | 外部信息 |
| 问赛事方：权重挂载还是打进镜像 | 外部信息 |
| 找一个有 Docker 的环境验证 | 需要环境 |
| 验证 `--network none` 下能跑 | 同上 |

**这一步可能需要队友或老师提供有 Docker 的机器。**

### P4：扩大评测规模

小规模（5 题）验证通过后：
- 扩到 20~30 题，观察规则在难题上是否还成立
- 挑出失败集中的题目，**给技能包提炼新材料**（队友 A 的任务）

### P5：全量 156 题 + 报告回填

⏱️ **时间预算**：单题约 85 秒（其中综合占 85%）→ 全量 156 题 × 5 采样 × 2 模式 ≈ **37 小时**。

**必须先小规模验证再上全量。**

## 五、如果综合永远解决不了：降级方案

**不要在这上面无限投入。** 理由：

1. **我们已证明流程正确**（同版本同器件在开发机综合成功）
2. **赛题最终评测环境大概率不是这台机器**
3. **这台机器仍有很大价值**——能产出**编译 + 仿真**两级的真实数据

**降级后的价值评估**：

| 赛题要求 | 能否满足 |
|---|---|
| 可编译 | ✅ 能测 |
| **仿真通过** | ✅ **能测（这是含金量最高的一级）** |
| 可综合 | ⚠️ 实验室机器测不了，但开发机验证过流程 |
| 增益 | ✅ 能用"编译+仿真"口径算 |
| 墙钟 | ✅ 能测（缺综合那一段） |

**结论**：降级后仍能产出**大部分关键数据**，报告里如实说明"综合因环境限制未能在实验室机器复现，但流程已在开发机验证"。

## 六、部署检查清单

### 在任何机器上部署，只需三步

| 步骤 | 命令 | 预期 |
|---|---|---|
| ① 拿到代码 | 下载 zip 或 `git clone` | 111 个文件 |
| ② 设环境变量 | `LOGICLENS_VIVADO`、`LOGICLENS_MODEL_URL`、`LOGICLENS_MODEL_NAME` | — |
| ③ 验证 | `python -m unittest discover -s tests` | **124 个全绿** |

**不需要**：pip install、编译、配置 PYTHONPATH、改代码。

**这就是"零依赖"设计的价值** —— 部署成本几乎为零。

### 模型服务的部署（独立于代码）

| 步骤 | 命令 |
|---|---|
| ① 装 Ollama | 下载安装包（Windows）或 `curl -fsSL https://ollama.com/install.sh \| sh`（Linux） |
| ② 设模型目录到大盘 | `OLLAMA_MODELS` 环境变量 |
| ③ 拉模型 | `ollama pull qwen2.5-coder:7b` |
| ④ 验证 GPU | `ollama ps` 看 `PROCESSOR` 是否为 `100% GPU` |
| ⑤ 记录配置 | `python serve/record_service.py --model <模型> --json` |
