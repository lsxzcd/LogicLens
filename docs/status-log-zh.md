### 3.2 做不了（受客观条件限制）

| 项目 | 限制原因 |
|---|---|
| **真实模型性能数据** | 本机无独立显卡，CPU 推理速度不足以支撑全量评测 |

| **ROCm/Vulkan 加速验证** | 需要 AMD 显卡和驱动栈 |
| **容器内模型自包含性验证** | 依赖 Docker + 模型权重 |

### 3.3 需要外部信息才能推进

| 需要的信息 | 用途 | 谁知道 |
|---|---|---|
| **官方基础镜像名称** | 写 Dockerfile | 赛题群 / FAQ 云文档 / 评分细则 |
| **AMD 机器显卡型号与显存** | 决定模型选型和量化方案 | 学校 |
| **决赛/评测环境的具体配置** | 复现验证 | 赛事方公告 |

### 3.4 ⚠️ 关键限制：本机没有独立显卡

实测结果：

```
Win32_VideoController: Intel(R) Iris(R) Xe Graphics   （仅此一个）
```

- 无 AMD Radeon、无 NVIDIA 独显
- Intel 核显**不支持 ROCm**
- Ollama 在本机只能 CPU 推理

**影响**：本机**只能验证链路正确性，不能产出正式性能数据**。
正式数据必须在学校提供的 AMD 显卡机器上产出，方案见 `docs/amd-machine-validation-zh.md`。

## 四、开发过程中发现并修复的真实缺陷

这些是**有证据、可复现**的缺陷，不是推测。列出来是为了让队友知道哪些坑已经填过。

| # | 缺陷 | 后果 | 状态 |
|---|---|---|---|
| 1 | 仿真失败判定含裸子串 `error` | 正确设计合法打印该词即误判 | ✅ 已修 |
| 2 | 综合阶段无 5 ns 时钟约束 | 赛题要求缺失，时序未验证 | ✅ 已修 |
| 3 | XDC 硬编码 `get_ports clk` | 组合逻辑题约束静默失效并被判失败 | ✅ 已修 |
| 4 | 仿真失败后仍跑综合 | **三级通过率虚高** | ✅ 已修 |
| 5 | 调 Vivado 无超时 | 单题卡死拖垮批量评测 | ✅ 已修 |
| 6 | 测试台路径硬编码在 3 个文件 | **换任何题都跑不通**（原设计单点瓶颈） | ✅ 已修 |
| 7 | `--mock` 固定读计数器答案 | 跑别的题会静默用错答案 | ✅ 已修 |
| 8 | **错误归因错阶段** | 综合失败被归为"仿真不一致"，**3 次重试全部浪费在不存在的问题上**，批量评测 pass@k 会无声偏低 | ✅ 已修 |
| 9~14 | 6 个接口解析缺陷（bullet 格式、停用词含 `a`、`[3:1]` 宽度算法、缩进代码块、`module with` 误匹配、代码块覆盖 bullet） | 解析正确率从 29/156 提升到 153/156 | ✅ 已修 |

**第 8 项最隐蔽**——它不会报错，只会让通过率莫名偏低。

## 五、队友如何开始

### 5.1 环境搭建

按 `docs/setup-zh.md` 操作。关键点：

- 只需要 **Python 3.11+**（项目**只用标准库**，无需 pip install）
- Vivado 路径**自动解析**，通常不用配；不行再设 `LOGICLENS_VIVADO`
- `xvlog`/`xelab`/`xsim` **不需要**单独配置（由 Vivado 批处理会话继承）

### 5.2 三项自检（开工前必做）

```powershell
git clone https://github.com/lsxzcd/LogicLens.git
cd LogicLens

py -3 -m unittest discover -s tests     # 期望 84 个全绿（不需要 Vivado）
py -3 tools/check_architecture.py       # 期望无硬编码
py -3 tools/check_parsing.py            # 期望 0 unexplained
```

有 Vivado 的话再跑：

```powershell
py -3 experiments\p05_verify.py         # 期望 3 cases, 0 failed, 0 env-blocked
```

### 5.3 可并行的分工（边界已定，不会冲突）

| 方向 | 负责 | 边界 |
|---|---|---|
| A. 数据集与测试台 | 扩展数据集、准备 sidecar testbench | 只加 `experiments/data/` 下文件 |
| B. 智能体与技能包 | 规格契约、多候选生成、局部修复、技能卡 | 只改 `agent/`、`skill/` |
| C. 模型与部署 | 推理服务、显存实测、`MODEL.md`、Dockerfile | 只碰 `agent/model_client.py`、新增部署文件 |

**三条铁律**（详见 `CONTRIBUTING.md`）：

1. 测试台只经 `agent/testbench.py::resolve_testbench`
2. 契约字段只经 `TaskContract`，新增必须向后兼容
3. 判定口径只在 `vivado/run_flow.tcl` 决定，改语义必须同步更新字段表

## 六、不变量（不要破坏）

| 不变量 | 为什么 |
|---|---|
| 统计三级通过率时**必须**用 `synthesis_attempted` 区分"没跑"和"跑了没过" | 否则通过率虚高 |
| `--mock` 结果**禁止**写进报告结论 | 赛题要求真实可复现数据 |
| 不要提交模型权重和大数据集 | Git 永久保存历史，仓库会被撑爆 |
| 不要硬编码 testbench 路径 | CI 有架构守卫会拦住，但别浪费一次 CI |
