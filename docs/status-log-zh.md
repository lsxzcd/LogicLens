### 2.4 真实模型链路 + 可测量的技能包改进 ⭐

本机装了 Ollama 0.40.2 + `qwen2.5-coder:1.5b`（CPU 推理），在 VerilogEval 前 5 道题上跑出**真实改进曲线**：

| 阶段 | pass@1 | 改了什么 |
|---|---|---|
| 基线 | **0.0** | — |
| + 接口契约规则 | **0.2** | 把端口列表渲染成 Verilog 声明，禁止凭空加 clock/reset |
| + 具体代码骨架 | **0.4** | 给两种形态的可复制模板（小模型对示例遵循度远高于抽象规则） |
| + 修复提示词改造 | **0.6** | **不再向模型展示失败代码**（见下） |
| + 结构检查器 | **0.8** | 仿真前先做静态结构检查 |

⚠️ **这 5 道题的数字不是性能结论**，只证明"每条规则确实改变了行为"。正式数据需跑全量 156 道。

**最有价值的单一发现**：把失败代码放进修复提示词，会让模型**逐字照抄**那段错误结构
（三次尝试 MD5 完全相同），无视错误信息和 seed 变化。对照实验：展示代码时 3/3 输出含
`posedge`；只给错误摘要时 **0/3**。

**新增 `agent/rtl_lint.py`**：从源码结构上判定两类错误（不需要跑仿真）
- 组合逻辑题里出现 `posedge`/`negedge`（含把数据端口当时钟沿）
- 输出由同一输入的移位切片在相同偏移处拼回，**等于原值**（字节交换却什么都没交换）

**技能卡**：`skill/skill_cards.json` 记录 6 张卡，每张含来源失败、证据、执行方式、**实测效果**、
以及 1 项明确的**未解决限制**（该模型即使拿到 lint 结果和编译错误，仍无法去掉凭空加的时钟）。

复现：
```powershell
# 需要本机 Ollama 服务与模型
$env:LOGICLENS_MODEL_URL="http://127.0.0.1:11434/v1"
$env:LOGICLENS_MODEL_NAME="qwen2.5-coder:1.5b"
$env:LOGICLENS_SEED="1"
py -3 eval.py --dataset experiments\data\verilogeval --mode agent --limit 5 --samples 1
```

## 四、开发过程中发现并修复的真实缺陷

**有证据、可复现**，不是推测。列出是为了让队友知道哪些坑已经填过。

| # | 缺陷 | 后果 | 状态 |
|---|---|---|---|
| 1 | 仿真失败判定含裸子串 `error` | 正确设计合法打印该词即误判 | ✅ |
| 2 | 综合阶段无 5 ns 时钟约束 | 赛题要求缺失，时序未验证 | ✅ |
| 3 | XDC 硬编码 `get_ports clk` | 组合逻辑题约束静默失效并被判失败 | ✅ |
| 4 | 仿真失败后仍跑综合 | **三级通过率虚高** | ✅ |
| 5 | 调 Vivado 无超时 | 单题卡死拖垮批量评测 | ✅ |
| 6 | 测试台路径硬编码在 3 个文件 | **换任何题都跑不通**（原单点瓶颈） | ✅ |
| 7 | `--mock` 固定读计数器答案 | 跑别的题会静默用错答案 | ✅ |
| 8 | **错误归因错阶段** | 综合失败归为"仿真不一致"，**3 次重试全浪费**，pass@k 无声偏低 | ✅ |
| 9~14 | 6 个接口解析缺陷（bullet 格式、停用词含 `a`、`[3:1]` 宽度算法、缩进代码块、`module with` 误匹配、代码块覆盖 bullet） | 解析正确率 29/156 → 153/156 | ✅ |
| 15 | **错误模式 `mismatch` 过宽** | 把 `port width mismatch` 等警告误判为仿真不一致 | ✅ |
| 16 | **固定 seed 使修复完全无效** | 本地服务在固定 seed 下完全确定（提高温度也无效），修复循环拿到逐字相同的代码 | ✅ |
| 17 | **修复提示词展示失败代码造成锚定** | 模型逐字照抄错误结构，3 次重试全部浪费（对照实验：展示 3/3 含错误结构，不展示 0/3） | ✅ |
| 18 | **新测试依赖未提交的 fixture 文件** | 本机（有全量 156 道导出）通过，**CI 干净克隆 `FileNotFoundError`，3 个检查全挂** | ✅ |
| 19 | 容器入口脚本无可执行位 | Windows 上 git 无法记录可执行位，容器里 `Permission denied` | ✅ |
| 20 | **基线无法接受模型参数** | `run_baseline.py` 没有 `--model-url`/`--model`/`--seed`；**两侧模型不同 → 增益数据完全不可信**（权重最高 40 分的那项） | ✅ |
| 21 | **评测时基线与智能体各建客户端** | 两处独立 `ModelClient()`，只要环境变量有差异就**无声不公平** | ✅ |
| 22 | `--mock` 在自带示例上不可用 | `resolve_reference_answer` 不认 `answer.v`，README 里那条命令**在唯一该跑通的题上直接失败** | ✅ |

**第 8、16、17、18、20、21 项最隐蔽**——都不会在本地报错，只会让通过率莫名偏低、让 CI 失败，或让增益数据不可信。

## 五、队友如何开始

### 5.1 环境搭建

按 `docs/setup-zh.md`。要点：
- 只需 **Python 3.11+**（项目**只用标准库**，无需 pip install）
- Vivado 路径**自动解析**，不行再设 `LOGICLENS_VIVADO`
- `xvlog`/`xelab`/`xsim` **不需要**单独配置（由 Vivado 批处理会话继承）

### 5.2 三项自检（开工前必做）

```bash
git clone https://github.com/lsxzcd/LogicLens.git
cd LogicLens

python3 -m unittest discover -s tests    # 期望 110 个全绿（不需要 Vivado）
python3 tools/check_architecture.py      # 期望无硬编码
python3 tools/check_parsing.py           # 期望 0 unexplained
```

有 Vivado 再跑：
```bash
python3 experiments/p05_verify.py        # 期望 3 cases, 0 failed, 0 env-blocked
```

> ⚠️ **推代码之前，用干净克隆再跑一遍测试。** 这是唯一能发现"依赖了未提交文件"的方法
> ——该缺陷曾让 3 个 CI 检查全挂（见 §四 第 18 项）。详见 `CONTRIBUTING.md`。

### 5.3 可并行的分工（边界已定，不会冲突）

| 方向 | 负责 | 边界 |
|---|---|---|
| A. 数据集与测试台 | 扩展数据集、准备 sidecar testbench | 只加 `experiments/data/` 下文件 |
| B. 智能体与技能包 | 规格契约、多候选生成、局部修复、技能卡 | 只改 `agent/`、`skill/` |
| C. 模型与部署 | 推理服务、显存实测、`MODEL.md`、Dockerfile | 只碰 `agent/model_client.py`、新增部署文件 |

**三条铁律**（详见 `CONTRIBUTING.md`）：
1. 测试台只经 `agent/testbench.py::resolve_testbench`
2. 契约字段只经 `TaskContract`，新增必须向后兼容
3. 判定口径只在 `vivado/run_flow.tcl` 决定，改语义必须同步更新字段表

## 六、不变量（不要破坏）

| 不变量 | 为什么 |
|---|---|
| 统计三级通过率**必须**用 `synthesis_attempted` 区分"没跑"和"跑了没过" | 否则通过率虚高 |
| `--mock` 结果**禁止**写进报告结论 | 赛题要求真实可复现数据 |
| **修复提示词不要展示失败代码** | 实测会让模型逐字照抄错误结构 |
| **测试不要依赖未提交的文件** | 本机过、CI 挂（已实际发生） |
| **推之前用干净克隆跑一遍测试** | 唯一能发现上一条的方法 |
| 不要提交模型权重和大数据集 | Git 永久保存历史，仓库会被撑爆 |
| 不要硬编码 testbench 路径 | CI 有架构守卫会拦住 |
